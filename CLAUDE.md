# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Read first

`STUDY_GUIDE.md` is the source of truth for the architecture, design decisions and known limitations.
The owner uses this project for interviews, so keep the code **simple and explainable**:
- Prefer small, readable steps over clever abstractions.
- Don't add features or infrastructure that aren't asked for.
- Update `STUDY_GUIDE.md` when behaviour changes.

## Layout

Three FastAPI services (Python 3.12, `uv`) plus a shared package:

- **`master/` (8000):** orchestrator.
- **`query/` (8001):** NL → KQL → Elasticsearch.
- **`rag/` (8002):** runbook retrieval over Qdrant.
- **`nexgen_shared/`:** Pydantic contracts (`schemas.py`) and error codes E001–E008 (`errors.py`).
  - It's the **only** code shared between services; they talk over HTTP only and never import each
    other's modules.
  - Each service depends on it via `[tool.uv.sources] nexgen-shared = { path = "../nexgen_shared" }`.

## Commands

Run from inside each component directory. Imports use the `src.` prefix, and paths resolve from there.

```bash
cd master && uv run pytest                       # also: cd query / cd rag / cd nexgen_shared (--extra dev)
cd rag && uv run pytest tests/unit/test_fusion.py::test_classify_query   # single test
cd master && MOCK_SERVICES=true uv run uvicorn src.main:app --port 8000   # Master without other services
cd master && uv run python eval/run_eval.py --mode rules|llm             # Master benchmark -> eval/RESULTS.md
tests/e2e/run.sh --limit 3        # full stack: Docker (ES+Qdrant), Ollama, Groq key in master/.env
rag/scripts/eval.sh               # RAGAS-style RAG eval -> rag/tests/eval/RESULTS.md
docker compose up -d elasticsearch qdrant redis
```

Tests that need live Elasticsearch, Qdrant or an LLM skip themselves when those aren't available. The RAG
eval also needs `RUN_RAGAS=1`. `RESULTS.md` files are generated by their scripts; don't edit them by hand.

## How it works (details in STUDY_GUIDE.md)

**Master** (`MasterOrchestrator.run`): intent (keyword rules, LLM fallback) → planner → executor → context
→ reasoner + validator → synthesiser.
- **Planner:** asks Query for *all* WARN/ERROR events across the named service and everything it depends
  on in `config/topology.json`.
- **Executor:** calls Query and RAG in parallel. Failures become `status="failure"` results with E003/E004.
- **Context:** de-duplicates the logs and applies a token budget.
- **Reasoner:**
  - Rules rank candidate services by when they first had a problem.
  - An optional LLM may only reorder those candidates.
- **Validator:** deterministic checks for topology reachability (E008), timing and grounding.
- **Synthesiser:**
  - Confidence = `0.6·log_support + 0.3·doc_support + 0.1·topology_ok`, computed in code.
  - Evidence item 0 is `root_cause` / `service:<name>`.
- **Config and LLM:**
  - LLM = any OpenAI-compatible API via `src/llm.py:ask_json`. Settings live in `src/settings.py` /
    `master/.env`. An empty `OPENAI_API_KEY` means rules-only.
  - `MOCK_SERVICES=true` serves `data/scenarios.json` through `src/fixtures.py` instead of HTTP.

**Query:** `schema_linker` → `few_shot` → `generator` → `validator` ⇄ `repair` (≤3 attempts, E002) →
`kql_dsl` → `executor` → `pii`.
- `schema_linker` picks indices by hint, else all indices.
- `few_shot` picks examples from `data/few_shot_examples.jsonl` by word overlap.
- `pii` masks personal data.
- LLM settings: `GROQ_API_KEY`, `GROQ_MODEL`.

**RAG:**
- **Ingest:** `rag/data/docs/*.md` (front-matter `doc_id`, `source_uri`, `authority_tier`) → chunks
  `<doc_id>-chunk-<n>` → Qdrant dense (Ollama `nomic-embed-text`, 768-dim, `/api/embeddings`) + sparse
  hashed term frequencies.
- **Query:** time filter → dense + sparse → weighted RRF → cross-encoder re-rank → authority
  (`sigmoid(logit)` × boosts) → NLI conflict → LLM debate → LLMLingua-2 compression **per chunk** + ID
  re-injection.
- `MIN_RELEVANCE_SCORE` is off by default. Debate LLM: `OLLAMA_BASE_URL` / `DEBATE_LLM_*`.

**Pinned versions:** `elasticsearch<9` (server 8.13) and `qdrant-client<1.10` (server 1.9; newer clients
removed `.search()`).
